# 認証未設定時の起動拒否

対象はmainの`4abe21d78d4f934c149e5665d3a9d148e7d59c74`。既存のWeb版の安全対策として、認証設定がないまま特権APIやターミナルを利用できる経路を閉じる。

## 確認した問題

HTTPミドルウェアとWebSocket認証関数は、`AUTH_TOKEN`が空だと認証成功を返していた。サーバーは`0.0.0.0`で待ち受ける。`.env.example`は`change-me`、Docker Composeは未設定時に`pdr-local`を使っていた。

既存の認証テストは`src/server/auth.ts`だけを対象としていた。本番ルートが使う`src/middleware/auth.ts`とWebSocketサービスの検証を追加する。

## 採用した設計

- 純粋関数で未設定・空文字・空白のみ・既知の2つのサンプル値を判定する
- `server.ts`の実行本体の先頭で検証し、不正ならHTTP/HTTPS/WSの作成前に例外で終了する
- 起動処理を通さず認証関数を呼んだ場合も、不正な設定なら必ず拒否する
- 空白除去は設定の妥当性判定だけに使う。正当なトークンの値を自動で変更しない
- Docker Composeの共通トークンへのフォールバックを取り除く
- エラー文は固定し、設定値を含めない

静的importは検証より先に実行されるため、ロガーやネイティブモジュールの読み込みまで防ぐ設計ではない。待受開始とターミナル実行を防ぐ。

## 反証ケースと却下した案

「警告だけ表示する」案では、設定漏れのままアクセスできる問題が残るため採用しない。
「localhostなら認証不要」案も採用しない。Host・Origin・転送ヘッダーは認証の根拠にしない。現状の`--host`指定はサーバーの待受先に反映されないため、安全な例外として扱えない。

起動時のトークン自動生成・保存は行わない。既存の設定やクライアントとの対応を勝手に変えず、利用者が自分の値を設定する。
最低文字数の一律適用や既存トークンの正規化は、今回の設定漏れ対策に不要な互換性変更になるため採用しない。十分に長いランダムな値の用意は利用者に求める。

WebSocketのプロトコル移行、Origin制約の追加、トークン比較方式の変更は別の変更として扱う。正しいBearerヘッダーとURLエンコードしたクエリトークンは、従来どおり使える。

## 検証

変更前の142テストに対し、変更後は190テストが成功した。通常の型検査、ESLint、server/client/cliのビルドも成功した。

- 本番HTTP認証とテスト用認証関数の両方で、不正な設定を拒否する
- 一致する空文字やサンプル値を送っても拒否する
- 有効な設定でも、トークンの欠落・誤り・Bearer表記の違いを拒否する
- WebSocketサービスは認証失敗時に4001で閉じ、メッセージハンドラやローカル/SSHセッションを開始しない
- Unicode、`+`、`/`、`=`、前後空白を含む有効な値の厳密一致を保つ
- クエリパラメータ重複時の先頭値を使う挙動を保つ。不正なURLは例外を漏らさず拒否する
- Host・Origin・転送ヘッダーにlocalhostを指定しても認証を省略しない
- 本物のエントリポイントを不活性なサーバーに差し替えて読み込み、不正な設定ではHTTP/HTTPS/WSを作成せず、listenやログディレクトリ初期化も呼ばないことを検証する
- ビルド済みサーバーを7つの環境設定で別プロセス起動し、不正な設定は待受作成前に終了、有効な設定は検証用の待受禁止ガードまで進むことを確認した。実際のポートは開いていない
- Compose設定から既定の共通トークンがなくなったことを検査した。Dockerでの実起動は未検証

設計と実装を別担当が確認し、認証関連の65テストを独立実行した。重大な指摘は残っていない。

CI全体が成功したという意味ではない。変更前のmainでも、Prettier検査は13ファイルで失敗し、追加の`tsconfig.test.json`型検査は既存の3件の動的import型エラーで失敗する。今回も同じ失敗を再現した。通常のESLintにも既存の未使用import警告が1件残る。

## 既存PRとの重複

- [#37](https://github.com/Y-Kanekoo/pocket-dev-relay/pull/37)は定時間比較などを含む。認証未設定時は警告だけで、今回の起動拒否とは異なる
- [#46](https://github.com/Y-Kanekoo/pocket-dev-relay/pull/46)はメッセージによるWS認証を追加するが、未設定時の許可を残す。取り込む際はWSの別の認証省略経路も確認し、今回の拒否条件が失われないようにする
- [#77](https://github.com/Y-Kanekoo/pocket-dev-relay/pull/77)はWeb版をTailscale/mosh/tmuxのCLIに置き換える。採用する場合は、このWeb版パッチを機械的に適用しない

このパッチは上記PRを取り込まない。公開・マージ前には、採用する製品構成と競合を再確認する。

## 残る制約

静的ファイルと`/api/health`は従来どおり認証不要。トークン照合の実行時間差、クエリトークンのログ流出、平文HTTP、WS認証試行の制限不足は残る。インターネットへの公開を安全と判断できる変更ではない。
